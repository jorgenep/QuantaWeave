# Intel GPU (verified on an Arc Pro B70 / Battlemage, `xe` kernel driver, Level-Zero runtime):
uv venv --python 3.12 .intel-venv
uv pip install --python .intel-venv/bin/python torch --index-url https://download.pytorch.org/whl/xpu
uv pip install --python .intel-venv/bin/python -e '.[data,tools]'
# Verify: .intel-venv/bin/python -c "import torch; print(torch.xpu.is_available(), torch.xpu.get_device_name(0))"
# Run the custom trainer with: MOE_PYTHON=.intel-venv/bin/python MOE_DEVICE=xpu ./scripts/run_quantweave_moe.sh
#
# Two things this exact stack gets wrong that cost real debugging time -- see PARAMETERS.md's
# "Intel XPU (Arc / Battlemage) caveats" section before sizing a long run:
#   - device OOM crashes the `xe` kernel driver (GPU page faults, 5+ minute hang) instead of
#     raising a clean Python exception, so --auto-batch-size / hardware.py --probe are NOT safe
#     here -- size the architecture by hand and test short capped runs instead.
#   - host system RAM, not GPU VRAM, is usually the binding constraint on this driver stack for
#     anything past a small model, because of how it stages memory through the host.
